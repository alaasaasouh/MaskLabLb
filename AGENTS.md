# Project workflow

- Make requested edits locally and complete appropriate checks first.
- Before pushing future changes to GitHub, summarize the completed changes and ask the user for approval. Push only after explicit approval for that push.
- An explicit request to upload or push the current changes is approval for that specific push; do not ask twice.
- Keep `.local/`, browser profiles, personal information, credentials and internal commercial notes out of Git and public hosting.
- Preserve the supplied brand and product assets. Use HTML, CSS and vanilla JavaScript; no framework or backend is required.
- Delivery, policies, sizing and care details remain pending owner input. Do not invent them.
- The video-to-website/frame workflow is deferred until the user requests it.
